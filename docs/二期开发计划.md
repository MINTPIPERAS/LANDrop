# LANDrop 二期开发计划

> 版本：v0.2.0
> 日期：2026-11-06
> 状态：阶段 0–6 已实施并出安装包；托盘交互与两机实传待人工验收
> 一期的范围与验收见 [项目计划.md](项目计划.md)

## 一、背景与目标

一期已经把「单文件、单主机、可靠送达」这条路走通：`.part` 续传、双端 SHA-256 校验、`RejectPolicy` 拒绝未知主机密钥、NSIS 安装包。但它仍然只能一次传一个文件、只记住一组连接信息、日志只写 WARNING 且永不清理、没有定时也没有开机自启。

二期要补的能力：

| 能力 | 解决的问题 |
|---|---|
| 多文件队列 | 一次只能挑一个文件、发完才能挑下一个 |
| 目录递归传输 | 只能传单文件，不能传文件夹 |
| 多设备记忆与切换 | 只存一组主机信息，换机器要重填 |
| 日志目录可配置 + 保留策略 | 日志不记成功传输、单文件无限增长、位置不可改 |
| 定时传输 | 到点无人值守发送 |
| 开机自启 + 托盘常驻 | 定时任务需要应用在场 |

两条贯穿全期的设计原则：

1. **不引数据库**。数据量是「几条设备 + 几个定时任务」，现有 `config.json` + 原子写入足够；密码继续交给 Windows 凭据管理器，比自建加密存储更稳妥。
2. **可靠性保证不退让**。新增的每一条路径（队列项、文件夹、定时任务）最终都走同一个 `upload_file`，续传与校验一个都不少。

## 二、当前存储模型

| 存什么 | 位置 | 现状 |
|---|---|---|
| 主机、端口、用户名、目标目录、认证方式、私钥**路径**、热键 | `%APPDATA%\LANDrop\config.json` | 原子写（临时文件 + `os.replace`） |
| 密码 | Windows 凭据管理器，目标名 `LANDrop/{用户名}` | DPAPI 加密、绑定当前 Windows 账户、不漫游 |
| 主机指纹 | `%APPDATA%\LANDrop\known_hosts` | App 自有，不用 `~/.ssh` |
| 私钥文件 | 用户指定位置 | 只存路径，不动文件 |
| 日志 | `%APPDATA%\LANDrop\service.log` | 单文件、仅 WARNING、永不清理 |
| 任务列表 | 内存 | 关掉即失 |

`config.json` 不允许出现明文密码，读取时发现直接报错。

**为什么不用数据库**：单用户桌面应用，数据量以条计；SQLite 会额外引入并发写锁、版本迁移和打包体积，换不到收益。而密码放数据库是退步——凭据管理器有系统级加密与账户绑定，是 `config.json` 和本地数据库都没有的保护。

**本期唯一需要改动的存储语义**：凭据条目名加入主机维度。现状是 `LANDrop/{用户名}`，多设备并存时同名用户会互相覆盖密码，表现为「明明存了密码却认证失败」。

## 三、需求与边界

### 3.1 多文件队列

- **做**：把多个文件或文件夹加入待发列表，按顺序逐个发送；每项独立显示进度；单项失败不阻塞后续；批次结束汇总成功/失败数；失败项可一键带覆盖重发。
- **不做**：队列持久化（关闭应用即清空）、并发发送（串行）、拖拽入队。
- **关键约束**：队列是前端概念，每项仍是一次独立的 `POST /api/transfers`，后端任务模型不变。

### 3.2 目录递归传输

- **做**：选一个文件夹作为来源，保留相对目录结构发送；自动创建远端子目录；空目录也建出来；软链接跳过并在结果里标注；单文件失败不中断整批。
- **不做**：增量同步（按 mtime 跳过未变更文件）、删除远端多余文件。
- **关键约束**：每个文件仍走 `upload_file`，既有续传与 SHA-256 校验逐文件生效。

### 3.3 多设备记忆与切换

- **做**：保存多台设备（名称、主机、端口、用户名、目标目录、认证方式、私钥路径），侧栏一键切换；旧配置自动迁移成第一台设备。
- **不做**：设备分组、设备级代理/跳板机。
- **关键约束**：密码不跟随设备存进 JSON，仍在凭据管理器，按 `主机:端口/用户名` 隔离。

### 3.4 日志目录与保留

- **做**：默认 `%APPDATA%\LANDrop\logs\`，设置里可改任意目录；按天滚动 + 单文件 10 MB 上限；INFO 级记录传输成败；保留天数可配（7/14/30/90/永久）；界面显示占用并可打开目录。
- **不做**：日志内容过滤、日志上报、任务历史的独立数据库。
- **关键约束**：目录不可写或盘符消失时降级为不写文件，绝不影响传输。

### 3.5 定时传输

- **做**：一次性 / 每天 / 每周三种模式；一个定时任务一个来源（文件或文件夹）；应用运行时由内置调度执行，应用关闭后由 Windows 计划任务执行；两套互斥，不重复发送。
- **不做**：每隔 N 小时、每月某天、每月最后一天（`schtasks` 命令行表达不了最后一天，需要改用 XML 定义）、多来源定时任务。
- **关键约束**：密码认证的定时任务必须先把密码存进凭据管理器，否则无人值守必然失败——保存时直接拒绝并提示。

### 3.6 开机自启 + 托盘

- **做**：注册表 Run 项开机自启（可在设置里开关）；启动时若路径变化自动修正；托盘常驻，关窗口只隐藏、不退出；托盘菜单可显示窗口、打开日志目录、退出。
- **不做**：开机自启的参数化配置（如「启动即发送某任务」）、多用户安装级自启。
- **关键约束**：开机自启与「关闭窗口时最小化到托盘」互不依赖，可单独开启；注册表是自启状态的唯一真值，配置文件不另存一份。

## 五、数据结构

### 5.1 配置新增字段

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `devices` | `list[DeviceConfig]` | `[]` | 设备列表；为空时由扁平字段迁移生成 |
| `active_device_id` | `str` | `""` | 当前设备；无效则回落第一台 |
| `log_dir` | `str` | `""` | 空表示用默认目录 |
| `log_retention_days` | `int` | `14` | 0..3650，0 表示永久保留 |
| `schedules` | `list[ScheduleConfig]` | `[]` | 定时任务 |
| `close_to_tray` | `bool` | `true` | 关闭窗口是否最小化到托盘 |

开机自启**不在此表**：注册表是唯一真值，配置文件不存。

### 5.2 DeviceConfig

```
{ id, name, host, port, username, remote_dir, auth_method, private_key_path }
```

- `id`：短随机串，创建后不变；定时任务用 `device_id` 引用它。
- `name`：显示名，默认 `username@host`，可编辑。
- 校验：`id` 唯一、端口 1..65535、`auth_method ∈ {password, key}`、密钥认证时私钥路径必须存在。

### 5.3 ScheduleConfig

```
{ id, name, enabled, source_path, recursive, device_id, remote_dir,
  overwrite, mode: once|daily|weekly, time: "HH:MM", date: "YYYY-MM-DD"|"",
  weekdays: [0..6], last_run_at: "", last_run_status: "" }
```

- `remote_dir` 为空表示使用设备默认目标目录。
- 校验：`device_id` 必须存在；`once` 必须有 `date`；`weekly` 至少一个 `weekdays`；`source_path` 必须存在；密码认证设备必须有已存凭据。

### 5.4 SourceItem（前端队列项）

```
{ key, path, kind: 'file'|'folder', size, fileCount? }
```

`size`/`fileCount` 来自 `/api/scan`，用于发送前展示规模；扫描失败时降级为「未知」，不阻塞入队。

### 5.5 TreeResult

```
{ files: [{ rel_path, remote_path, size, ok, error, error_code }],
  ok_count, failed_count, skipped: [{ path, reason }],
  size, sha256: null, resumed_from: 0 }
```

文件夹任务的结果以此结构替换单文件的 `remote_path/sha256`；单文件任务保持原结构，前端按 `result.files` 是否存在区分。

### 5.6 错误码

| code | 含义 | 前端处理 |
|---|---|---|
| `target_exists` | 远端同名文件已存在 | 展示「覆盖并重发」 |
| `auth_failed` | 认证失败（含私钥带口令） | 提示检查密码/私钥 |
| `host_key_changed` | 主机密钥变化 | 提示重新校验指纹，禁止自动继续 |
| `verify_failed` | SHA-256 不一致 | 提示清理远端 `.part` |
| `state_conflict` | 远端临时文件大于本地 | 提示手动清理 |
| `local_changed` | 本地文件传输中被修改 | 提示重新选择 |
| `timeout` | 连接超时 | 提示检查防火墙/网段 |
| `transfer_failed` | 其他 | 显示原始消息 |

## 七、队列模型

### 7.1 为什么队列项是「来源」而不是「文件」

一个 120 个文件的文件夹如果拆成 120 个队列项，任务表会被瞬间刷屏，取消和重试也变得难以操作。所以队列里的一项 = 一个文件或一个文件夹；文件夹作为单个任务发送，内部逐文件传输并聚合进度。

### 7.2 派发流程

```
加入来源 → 入队（按路径去重）
   ↓ 点击「发送 N 项」
按顺序取第一项 → POST /api/transfers（文件 recursive=false / 文件夹 recursive=true）
   ↓ 订阅 SSE，直到终态
成功 → 继续下一项        失败 → 记录，继续下一项
   ↓ 全部结束
汇总：成功 N / 失败 M，失败项可单条重试或一键覆盖重发
```

### 7.3 策略表

| 场景 | 行为 |
|---|---|
| 单项失败 | 不中断队列，继续下一项，记入失败清单 |
| 重名冲突 | 该项以 `target_exists` 失败；批次结束后可「覆盖并重发失败项」 |
| 取消 | 停止派发 + 取消当前任务；剩余项保留在队列中，不自动发送 |
| 重复添加同一路径 | 去重并提示，不报错 |
| 应用关闭 | 队列清空；传输中断的部分靠远端 `.part` 续传，重新添加后自动接续 |

### 7.4 与后端线程池的关系

后端 `TransferManager` 是 2 线程池，队列串行派发只占用 1 个。剩下的并发能力留给「定时任务与手动任务同时发生」这种跨来源场景，不用于同一次队列。

## 八、定时三路模型

### 8.1 三条执行路径

| 路径 | 触发者 | 界面 | 适用 |
|---|---|---|---|
| 应用内调度线程 | 30 秒滴答 | 有进度 | 应用在运行（含托盘常驻、开机自启） |
| Windows 计划任务 | `schtasks` 到点 | 无 | 应用已退出 |
| 「立即执行」按钮 | 用户点击 | 有进度 | 手动补发 |

### 8.2 去重机制

sidecar 启动时对 `%APPDATA%\LANDrop\run.lock` 取 `msvcrt` 独占锁并持有到退出；`--run-schedule` 执行体先抢同一把锁，抢不到就记「应用正在运行，跳过本次」后正常退出。

| 时刻 | 应用状态 | 锁持有者 | 结果 |
|---|---|---|---|
| 到点 | 运行中 | GUI sidecar | 计划任务跳过；应用内线程派发，进度可见 |
| 到点 | 已退出 | 无人 | 计划任务抢到锁，无界面执行并写日志 |
| 到点 | 正在启动 | 先到先得 | 一方执行，另一方跳过 |

不使用 `os.kill(pid, 0)` 判断进程存活——在 Windows 上该调用可能真的终止目标进程。

### 8.3 系统任务映射

| 模式 | schtasks 参数 |
|---|---|
| 一次性 | `/SC ONCE /SD MM/DD/YYYY /ST HH:MM` |
| 每天 | `/SC DAILY /ST HH:MM` |
| 每周 | `/SC WEEKLY /D MON,TUE,... /ST HH:MM` |

任务名为 ASCII（`LANDrop-<id前8位>`），避免中文编码问题；下次运行时间由程序自己算，不解析 `schtasks` 的本地化输出。

### 8.4 开发护栏与错过执行

- 只有 `sys.frozen` 为真（打包后的 sidecar）才注册系统任务；开发模式只计算下次时间并在界面提示，避免把 `python.exe` 临时路径写进系统任务列表。
- 错过判断：`next_run_at` 已过且 `last_run_at` 早于它 → 界面标「上次未执行」，可一键补发。不使用 XML 的 `StartWhenAvailable`，保持实现简单。

### 10.2 手动验收（9 条）

1. 一次多选 5 个文件加入队列，确认逐个发送、任务表 5 行、批次结束显示成功/失败数。
2. 队列混合「2 个文件 + 1 个文件夹」：文件夹内部逐文件传且显示「第 n/m」，成功后结构与空目录都在。
3. 让队列中一项因重名失败：后续项继续发；点「覆盖并重发失败项」后该项成功。
4. 中途取消：立刻停在当前文件，剩余项不自动发送；再次发送能续传。
5. 两台设备（同一用户名、不同密码）来回切换各传一次，密码不串。
6. 日志目录改到 `D:\landrop-logs`：新日志落在新目录、旧文件留在原处并有提示；保留天数改成 7 天后过期文件被删。
7. 2 分钟后的一次性任务：应用开着时执行且进度可见；关闭应用后同一任务由 `--run-schedule` 执行，日志有记录、`last_run_at` 已更新。
8. 常驻托盘时到点：日志出现「跳过本次」，日志里能看到「跳过本次」，全局只有一份传输；关窗后进程仍在，托盘「退出」后进程消失。
9. 开机自启：开关后注册表出现 `LANDrop` 值且路径正确，重启后自动启动、窗口不弹出、托盘有图标；关掉开关后值消失；手动改错路径后重启应用被自愈。

## 十一、风险与取舍

| 风险 | 影响 | 处理 |
|---|---|---|
| 队列只在内存 | 关闭应用后待发列表丢失 | 传输本身的续传不受影响，重新添加即可接续 |
| 卸载残留 Run 项 | 指向已删路径，Windows 静默忽略 | 接受；开关可手动关闭；彻底清理需 NSIS 钩子 |
| 定时依赖登录状态 | 未登录时不触发 | 用户级任务、无需管理员；界面写明 |
| 凭据键只前向兼容 | 回退旧版本读不到新密码 | 需重输一次；旧键保留不删 |
| 自定义日志目录不可用 | 盘符消失、网络盘掉线 | 降级为不写文件，不影响传输 |
| 自动创建远端子目录 | 路径填错会在远端生成空目录 | 发送前显示目标根路径与项数供确认 |
| 托盘/自启/计划任务无法单测 | 回归只能靠手动 | 固定手动验收 8–9 条 |
