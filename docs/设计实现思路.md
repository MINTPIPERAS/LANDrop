# 局域网文件传输工具设计实现思路

## 1. 目标与范围

本文基于 [DeepSeek思路方案.md](DeepSeek思路方案.md)，将技术草案收敛为一套可分阶段开发、测试和发布的实现方案。项目采用 **Vue 3 + Tauri 桌面壳 + Python 本地传输服务**：Vue 负责界面，Tauri 提供 Windows 桌面能力，Python/Paramiko 负责 SSH/SFTP 传输。当前传输核心已初步实现，桌面前端和本地服务通信尚未实现。

### 首版目标（MVP）

- Windows 桌面客户端，支持选择单个本地文件并通过 SSH/SFTP 发送到远端。
- 支持大文件以及可恢复的断点续传。
- 支持配置远端地址、端口、用户名、目标目录和认证方式。
- 界面展示进度、速度、状态和错误，传输不阻塞 UI。
- 提供可配置的 Windows 全局热键，用于显示或唤起主窗口。
- 提供可重复构建的 Windows 桌面安装包。

### 首版不做

多文件队列、目录递归、局域网设备发现、NAT 穿透、自动开机启动、自动无限重试、传输后删除源文件。先把单文件传输、恢复、身份校验和错误反馈做可靠，再扩展这些功能。

## 2. 推荐技术选择

| 层 | 选择 | 说明 |
|---|---|---|
| 前端 | Vue 3 + TypeScript + Vite | 实现桌面界面；保持前端不接触 SSH 凭据和 Paramiko |
| 桌面壳 | Tauri 2 | 管理原生窗口、文件选择、全局快捷键与打包 |
| 本地服务 | Python 3.11+ | 承载现有传输模块、配置和凭据访问 |
| SSH/SFTP | Paramiko | SSH 认证、主机密钥校验、SFTP 文件读写 |
| 服务通信 | Tauri Rust sidecar 管理 Python 子进程；本机 HTTP API + SSE 事件 | 服务只绑定 loopback；传输凭据通过受控请求传入，不暴露给远端网络 |
| 配置 | JSON 普通配置 + Windows Credential Manager | 普通设置与敏感密码分开保存；私钥默认只保存路径 |
| Python 打包 | PyInstaller `onedir` | 先验证 sidecar 目录包，再由 Tauri 安装包收纳；首版不强求单文件 exe |
| 测试 | pytest + SFTP mock；前端 Vitest；Tauri 集成测试 | 核心传输和 UI 状态分别测试，另做真实远端验收 |

本机 API 应在启动时绑定随机可用端口，并使用随机会话令牌校验请求；限制 CORS/Origin，仅允许本应用 WebView 来源。令牌不得写入日志、URL 或持久配置。不要使用固定端口且无鉴权的本地服务。

## 3. 总体结构

```text
Vue 3 WebView
  ├─ 连接配置、文件选择、发送、进度与状态
  └─ 通过 Tauri command 请求启动/停止 Python sidecar
       └─ 本机 HTTP API + SSE
            └─ Python 服务进程
                 ├─ 配置和凭据适配
                 └─ Paramiko SFTP 传输核心
                      └─ 远端 SSH/SFTP 主机

Tauri 原生层
  ├─ 原生文件选择对话框
  ├─ 全局快捷键注册
  ├─ sidecar 生命周期、随机端口与会话令牌
  └─ 窗口显示、聚焦和退出清理
```

Vue 仅将文件选择结果交给 Tauri/Python；本地服务根据授权路径读取文件。传输状态通过 SSE 发回，前端断线重连后应可查询任务快照。外部网页或远端主机不能直接访问本机 API。

## 5. 本地服务 API 与进程边界

首版可采用轻量 HTTP 框架（例如 FastAPI/Uvicorn）运行 loopback 服务，具体框架在创建 API 模块时锁定。接口建议如下：

- `GET /health`：sidecar 就绪状态，仅允许带会话令牌访问。
- `POST /api/transfers`：提交一个传输任务，返回任务 ID；请求包含连接参数、文件路径和目标目录。
- `GET /api/transfers/{id}`：获取任务状态快照。
- `GET /api/transfers/{id}/events`：SSE 推送阶段、进度、速度和结束结果。
- `POST /api/transfers/{id}/cancel`：请求取消；服务保留远端 `.part`。
- `GET/PUT /api/config`：读写非敏感配置。凭据应经系统凭据库接口管理，不通过此接口返回明文。

所有接口都验证随机令牌；请求体大小和路径应做限制；不提供任意文件读取、任意命令执行或通用代理接口。任务 ID 使用不可预测标识。sidecar 退出时停止接收新任务、取消或等待正在执行的任务，并关闭 SSE 连接。

## 6. 传输协议与续传设计

### 6.1 文件命名与覆盖规则

最终目标文件和未完成文件分开。远端传输过程中写入同目录临时文件，例如 `report.zip.landrop.part`；最终文件仅在上传完成并通过验证后出现。首版遇到已有最终文件时不静默覆盖：界面提示并允许取消或明确覆盖。覆盖只使用远端支持的原子替换改名；不支持时报告错误，不先删除旧文件。

### 6.2 上传状态机

1. 获取本地文件大小和修改时间，记录传输任务元信息。
2. 连接远端，验证服务器主机密钥，并确认目标目录可用。
3. 查询临时文件大小；不存在则从 0 开始。若临时文件大于本地文件，作为状态冲突处理，不得当作成功。
4. 本地 `seek(offset)`，远端临时文件以追加模式打开，传输剩余数据并报告累计进度。
5. 取消或断线时关闭句柄并保留临时文件；重试时重连并重新查询长度。
6. 完成后确认远端长度与源文件一致，并检查源文件未在传输期间变化。
7. 计算源文件和远端临时文件 SHA-256；一致后改名为最终文件，不一致则失败并保留临时文件。

全文件哈希需要额外读取远端数据，尤其对大文件成本较高，但首版优先保证完整性，并在 UI 中展示校验阶段。服务端不支持安全覆盖改名时必须明确失败。

### 6.3 取消与恢复

首版不做后台无限重试。网络异常时保留 `.part`，显示错误和“重试”操作；重试重新建立连接并检查远端临时文件。任务状态保存在内存即可，应用重启后用户重新提交同一文件时仍可通过 `.part` 续传。

## 7. 安全与配置

- **主机密钥**：禁止默认自动接受。使用 known_hosts 校验；首次连接显示指纹，经用户确认后保存。主机密钥变化时阻止连接。
- **认证**：优先支持 SSH 私钥（可选口令），其次密码。密码不写普通 JSON、日志或 URL；需要记住密码时由 Python 层调用 Windows Credential Manager。
- **本地 API**：仅监听 loopback；随机端口和高熵会话令牌由 Tauri 原生层生成并经安全通道交给 sidecar。设置请求来源校验和令牌轮换/退出失效。
- **Tauri 权限**：只开放所需文件选择、窗口、快捷键和 sidecar 命令；避免给 WebView 泛化 shell 或文件系统访问权限。
- **日志**：不记录密码、私钥内容、会话令牌或文件内容。
- **远端路径**：只写用户配置目录；拼接文件名使用 basename 并校验越界路径。不假设所有 SFTP 服务端对 Windows 盘符路径格式相同。

## 8. 前端与任务交互

Vue 界面包含连接配置、认证方式、目标目录、文件选择、发送/取消、进度、速度、当前阶段和错误详情。传输时锁定当前任务配置，避免修改表单导致任务参数不一致。状态包含“连接中、检查续传、传输中、校验中、完成、已取消、失败”。

前端通过 store 管理任务快照，通过 SSE 接收事件；网络断开时指数退避重连，再调用状态接口同步当前快照。进度使用字节整数，格式化和百分比在显示层计算；零长度文件也需有确定状态。取消通过 API 请求，后端使用线程安全取消标志，不由 Vue 直接终止 Python 线程或 SSH 连接。

## 9. 分阶段实现

### 阶段一：工程与配置基础

保留现有 Python 包、配置模块和 Paramiko 传输核心；新增 Vue 3/Vite 前端和 Tauri 2 壳骨架。建立统一开发启动说明，确保前端、Rust 壳和 Python 测试可分别运行。

**完成条件**：开发模式可启动桌面窗口；前端可调用一个无敏感数据的 Tauri command；Python 配置测试通过。

### 阶段二：本机 API 与 sidecar 生命周期

为 Python 服务增加 loopback API、随机端口/会话令牌验证、健康检查和进程退出清理；Tauri 启动 sidecar 并安全传递运行参数；Vue 能连接服务并显示服务状态。

**完成条件**：无令牌、错误令牌和非 loopback 请求被拒绝；关闭应用后 sidecar 能退出；就绪/失败状态可见。

### 阶段三：传输核心 API 化

将现有 `upload_file` 纳入任务管理器；提供创建任务、查询、SSE 进度、取消和错误映射接口。认证信息只在任务请求中短暂传递，密码持久化由安全凭据适配器处理。

**完成条件**：API mock 测试覆盖创建、进度、取消、失败、重试和事件重连；既有 SFTP 单元测试继续通过。

### 阶段四：Vue 主界面

实现连接配置表单、文件选择、目标目录、发送/取消和任务进度页面；通过 Tauri 文件选择 command 获取路径，通过 API 管理传输任务；实现 SSE 重连和状态同步。

**完成条件**：实际桌面窗口中可完成配置、选择文件、开始/取消传输和查看状态；传输期间 UI 保持响应。

### 阶段五：快捷键与原生桌面体验

用 Tauri 全局快捷键能力注册/注销热键；冲突时降级为普通窗口操作；实现窗口唤起、聚焦和退出清理。确认具体 Tauri 插件/API 与所用 Tauri 版本兼容。

**完成条件**：窗口失焦时热键可唤起；热键占用不影响主功能；退出时 sidecar、事件流和热键均清理。

### 阶段六：集成测试与安全验收

用 Windows 和（可用时）Linux OpenSSH Server 进行真实测试，覆盖大文件、新传、取消后续传、断网恢复、冲突、凭据失败、主机密钥变化和路径权限；审查本机 API 的绑定地址、令牌、CORS、Tauri capabilities 和日志。

**完成条件**：大于 4 GiB 文件哈希一致；真实服务端续传和提交改名成功；本机服务不能被局域网其他设备访问。

### 阶段七：打包与发布

分别构建 Vue 静态资源、Tauri 应用和 Python sidecar；用 PyInstaller `onedir` 验证后由 Tauri bundle 收纳；在干净 Windows 环境验证首次启动、配置目录、凭据、升级和卸载行为。

**完成条件**：发布包不依赖开发机 Python/Node；应用退出不遗留后台服务；升级保留用户配置且不泄露认证信息。

## 10. 测试与验收

- Python：配置、主机密钥、续传偏移、追加写入、哈希、取消、错误和改名的 pytest/mock 测试。
- API：令牌校验、loopback 绑定、任务状态、SSE 重连、取消竞争和异常映射测试。
- Vue：表单校验、任务状态变化、SSE 断线重连与错误展示的 Vitest 测试。
- Tauri：sidecar 启停、文件选择、快捷键冲突、窗口唤起和能力权限的 Windows 集成测试。
- 手工集成：Windows 客户端连接 Windows/Linux OpenSSH；使用大于 4 GiB 文件验证传输并比对 SHA-256。

## 11. 主要风险与处理

| 风险 | 处理方式 |
|---|---|
| sidecar 端口被抢占或本机 API 被滥用 | 随机端口、loopback 绑定、高熵令牌、来源校验；启动失败时不降级为无鉴权 |
| Tauri 与 Python 生命周期脱节 | Tauri 原生层统一启动/停止 sidecar；异常退出时检测并清理子进程 |
| 多技术栈增加构建和调试成本 | 前端、Python 服务、Tauri 壳分别测试；先打通开发模式，再做发布构建 |
| Vue WebView 权限过大 | 配置最小 capabilities，只暴露必要 command |
| 远端 SFTP 对追加或 rename 支持差异 | 以真实 OpenSSH 集成测试为准；失败时保留 `.part` 并明确报错 |
| 全文件校验耗时 | 显示校验阶段，记录性能数据后再评估优化 |
| 热键被占用 | 注册失败降级，不影响窗口和传输 |

## 12. 与原始草案的差异

1. GUI 从 PySide6 改为 Vue 3，桌面能力由 Tauri 提供。
2. Python/Paramiko 作为独立本地服务运行，不在 WebView 中执行网络传输。
3. 移除 QThread 与 Qt 原生事件过滤器设计；线程/任务管理放 Python 服务，热键交由 Tauri 原生层。
4. 不再用 PyInstaller 单独产出完整 GUI exe；PyInstaller 只用于打包 Python sidecar，再由 Tauri 组装应用。
5. 沿用已实现的 `.part` 续传、哈希校验、known_hosts 拒绝未知主机和安全改名逻辑。
