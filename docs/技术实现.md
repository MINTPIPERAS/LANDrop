本文档描述 LANDrop 当前的实现方式：各层职责、一次传输从点击到落盘的完整路径、关键安全机制，以及代码在仓库中的具体位置。面向要读代码或继续开发的人。

## 1. 项目是什么

LANDrop 是一个 Windows 桌面工具：把本机的单个文件，通过 SSH/SFTP 发送到一台已配置好的远端电脑（Windows 或 Linux，需运行 OpenSSH Server），支持大文件断点续传、SHA-256 完整性校验，以及窗口失焦时的全局热键唤起。

它不是"局域网发现 + 直传"式的工具。没有设备发现、没有 NAT 穿透、没有自建传输协议：远端必须已经有可登录的 SSH 服务，LANDrop 只负责把文件可靠地写过去。

## 3. 核心原理：为什么是三层

```
┌──────────────────────────────────────────────────────┐
│ ① Vue 3 WebView（UI 进程内）                          │
│    表单、文件选择、进度条、状态展示                      │
│    只做：渲染 + 调用 Tauri command + 带令牌调本机 HTTP   │
└───────────────┬──────────────────────────┬───────────┘
                │ invoke('service_status')  │ fetch + SSE
                ▼                          ▼
┌──────────────────────────────┐  ┌──────────────────────┐
│ ② Tauri 2 / Rust             │  │ ③ Python 本机服务      │
│    · 生成随机端口 + 令牌       │  │    FastAPI + Uvicorn   │
│    · spawn Python sidecar     │  │    仅监听 127.0.0.1     │
│    · /health 就绪探测          │  │    ThreadPoolExecutor  │
│    · Windows Job Object       │  │    Paramiko ──────────┼──► 远端 SSH/SFTP
│    · 全局快捷键、窗口唤起       │  │    配置 / 凭据 / known_hosts
└──────────────────────────────┘  └──────────────────────┘
```

三层不是为了"技术炫技"，各自解决一个具体问题：

**为什么传输不放在 WebView 里？** WebView 里拿不到裸 TCP/证书链，也不该持有 SSH 私钥和密码明文。把网络与凭据关进独立进程，WebView 即使被 XSS 也只能调本机 API 上那几个受限接口。

**为什么需要 Rust 层，而不是让前端自己起 Python？** 前端无权创建进程、无法可靠地回收子进程，也不能安全地生成并传递高熵令牌。Rust 层是唯一同时具备"创建子进程""生成随机数""绑定 Windows Job Object"能力的地方。

**为什么不直接用 Tauri 的 Rust SSH 库？** 已有可用的 Paramiko 传输核心（`.part` 续传 + 哈希校验 + host key 拒绝），复用它可以少写一遍最容易出错的部分：断点偏移、追加写、原子改名。

## 4. 一次传输的完整链路

### 4.1 启动

1. `tauri::Builder` 在 `setup()` 中立刻调用 `ServiceState::start()`（`src-tauri/src/lib.rs:39`）。
2. `reserve_port()` 绑定 `127.0.0.1:0` 取一个空闲端口后立即释放（`service.rs:112`）。
3. `session_token()` 用 `getrandom` 生成 32 字节随机数，转成 64 位十六进制串（`service.rs:123`）。
4. `service_command()` 决定启动什么（`service.rs:131`）：先找 exe 同目录的 `landrop-service/landrop-service.exe` 或 `landrop-service.exe`（打包形态）；找不到且是 debug 构建时，退回 `python -m landrop.api.app` 并把 `PYTHONPATH` 指向仓库 `src/`。
5. 端口与令牌通过**环境变量** `LANDROP_SERVICE_PORT` / `LANDROP_SERVICE_TOKEN` 传给子进程（`service.rs:63`），不经过命令行参数（命令行会被其他进程看到）。
6. 子进程 stdin/stdout/stderr 全部丢弃，避免管道缓冲阻塞。
7. 立刻把子进程加入 Windows Job Object，标志 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`（`job.rs:18`）。
8. `wait_until_ready()` 每 120 ms 发一次原始 `GET /health`（手写 HTTP 报文，不引入 HTTP 客户端依赖），最长等 30 秒；期间若子进程已退出则立刻失败（`service.rs:175`、`service.rs:190`）。
9. 前端 `onMounted` 调 `connectService()` → `invoke('service_status')` 拿到 `{ baseUrl, token }`，缓存在模块变量里（`api.ts:84`）。

Python 侧 `run()` 从环境变量读端口与令牌，校验端口范围与令牌长度（< 32 字符直接拒绝启动），然后 `uvicorn.run(host="127.0.0.1")`（`app.py:517`）。

### 4.2 主机身份确认（首次连接某台远端）

这是唯一"用户参与的安全决策"，独立成一条流程：

1. `POST /api/hostkeys/probe` → `hostkeys.probe()`。
2. `_fetch_key()` 用一个假用户名 `landrop-probe` 发起连接，并安装 `_CapturePolicy`：策略在 `missing_host_key` 里**只记录密钥然后抛异常**，连接因此中断（`hostkeys.py:51`、`hostkeys.py:80`）。密钥已经拿到，但没有完成认证。
3. 指纹按 OpenSSH 风格计算：`SHA256:` + base64(SHA-256(公钥字节))，去掉尾部 `=`（`hostkeys.py:46`）。
4. 界面显示密钥类型与指纹，用户核对后 `POST /api/hostkeys/trust`。
5. `trust()` **重新取一次密钥**，比对指纹仍等于用户看到的值才写入（`hostkeys.py:124`）。不一致就拒绝，防止探测与保存之间被换掉。
6. 写入的是应用私有文件 `%APPDATA%\LANDrop\known_hosts`，不动用户的 `~/.ssh/known_hosts`（`hostkeys.py:34`）。

### 4.3 传输

前端 `send()`（`transfer.ts:253`）先持久化非敏感配置，必要时把密码写入凭据管理器，然后 `POST /api/transfers`。

`TransferManager.start()`（`app.py:176`）做四件事：
- 校验本地文件存在、私钥文件存在（如果指定了）。
- 取密码：请求里的密码优先；没有就去凭据管理器按用户名取；还没有就报错。
- 把 `password` 从保存的 request 副本里抹掉（`request.model_copy(update={"password": None})`），密码只挂在任务对象的私有字段上。
- 建任务、入表、提交到 `ThreadPoolExecutor(max_workers=2)`。

传输线程 `_run()`（`app.py:250`）按阶段推进并不断 `publish()` 快照：

```
queued → running/connecting → checking → transferring → verifying → succeeded
                                                │
                                                ├→ cancelled（保留 .part）
                                                └→ failed（保留 .part）
```

真正的文件操作在 `upload_file()`（`resume.py:98`）：

1. **路径计算**：`final = posixpath.join(remote_dir.rstrip("/"), basename)`；`partial = final + ".landrop.part"`。用 `posixpath` 而非 `os.path`，因为远端是 POSIX 语义。
2. **本地基线**：记录 `(size, mtime_ns)` 作为 `initial_signature`，之后在三个时点复核——传输后、哈希前、rename 前，防止用户一边传一边改文件。
3. **连接与验签**：`load_system_host_keys()` 读取系统与用户 known_hosts 用于**校验**（只读），再 `load_host_keys(app_known_hosts)`，最后装 `RejectPolicy()`。未知主机直接抛 `SSHException`，被包装成 `TransferError`。
4. **认证**：密码方式显式关闭 `allow_agent` / `look_for_keys`，避免出现"密码错了却用 agent 里别的身份混进去"；私钥方式可留空走 agent 或 `~/.ssh` 默认键。
5. **目标冲突**：若最终文件已存在且 `overwrite=False`，立刻失败——不静默覆盖。
6. **取偏移**：`offset = stat(partial).st_size or 0`。三种情况：
   - `offset > total`：远端残留比本地还大，判定状态冲突，报错且不截断。
   - `offset == total`：上次其实已传完但没来得及改名。跳过写入，直接进入校验。
   - 其余：`source.seek(offset)`、`sftp.open(partial, "ab")` 追加写，1 MiB 一块，每块检查取消标志并回调进度。
7. **完整性校验**：先比远端长度 == 本地长度，再**两边各算一次 SHA-256**（本地流式读，远端流式读），不一致就失败并保留 `.part`。这是"宁可慢也不发布坏文件"的选择，大文件会多花一次全量读取的时间。
8. **发布**：`overwrite=False` 用 `sftp.rename`（目标已存在会失败）；`overwrite=True` 用 `sftp.posix_rename`（原子替换）。若服务端不支持原子覆盖改名，直接报错，**不采用"先删旧文件再改名"**——那会在两步之间留下空窗（`resume.py:78`）。
9. **清理**：`finally` 里关 SFTP 与 SSH 客户端；`_run` 的 `finally` 把 `task.password` 置空。

### 4.4 进度回传与前端渲染

后端不用 WebSocket，用 SSE：

- 每个任务持有 `threading.Condition` 和一个 `deque(maxlen=256)` 事件环形缓冲，事件 id 单调递增（`app.py:118`）。
- `report_progress()` 用 `time.monotonic()` 算瞬时速度：`(本次已发 - 上次已发) / 间隔`（`app.py:254`）。
- `GET /api/transfers/{id}/events` 是一个生成器：阻塞等新事件（最多 10 秒），没事件就吐 `: keep-alive\n\n` 注释行保活；读到终态就结束流（`app.py:459`）。
- 前端 `subscribeTransfer()`（`api.ts:197`）用 `fetch` + `ReadableStream` 手写 SSE 解析（按 `\n\n` 切帧，取 `data:` 与 `id:` 行），记录 `lastEventId`。断线后按 1s→2s→4s→8s 指数退避重连，并把 `Last-Event-ID` 带上；服务端从该 id 之后补发，因此断网期间的事件不会丢。
- 终态任务由 `upsert()` 主动关闭对应流（`transfer.ts:123`）。
- 另有一条兜底：流报错时额外 `GET /api/transfers/{id}` 拉一次快照（`transfer.ts:133`）。

界面状态映射（`transfer.ts:98`）：

| 后端 status | 后端 phase | 界面文字 |
|---|---|---|
| queued | queued | 排队中 |
| running | connecting | 连接中 |
| running | checking | 检查续传 |
| running | transferring | 传输中 |
| running | verifying | 校验中 |
| succeeded | completed | 已完成 |
| failed | failed | 失败 |
| cancelled | cancelled | 已取消 |

## 5. 本机 API 的信任模型

服务只监听 `127.0.0.1`，但"只在本机"不等于"只有本应用能调"——同机上的任何进程、以及任意网页的 `fetch`，都能打到 loopback。所以叠了四道：

1. **网络层**：`uvicorn.run(host="127.0.0.1")`，绑定 loopback 网卡，局域网设备连不上。
2. **客户端地址中间件**：`enforce_local_caller` 解析 `request.client.host`，`ipaddress.is_loopback` 为假就 403（`app.py:333`）。这层防的是误配成 `0.0.0.0` 或反向代理场景。
3. **Origin 白名单**：允许的只有 `http://127.0.0.1:1424`、`http://localhost:1424`（Vite 开发）与 `tauri://localhost`、`http://tauri.localhost`、`https://tauri.localhost`（打包 WebView）。带 `Origin` 但不在名单内 → 403。浏览器发起的跨站请求必然带 `Origin`，于是一条普通网页的 `fetch` 就被挡住；同时 CORS 也只放这些来源。
4. **会话令牌**：`X-LANDrop-Token` 或 `Authorization: Bearer`，用 `hmac.compare_digest` 做常数时间比较（`app.py:350`）。令牌由 Rust 在每次启动时新生成，64 位十六进制，只存在于内存与子进程环境变量里，不落盘、不进 URL、不进日志。

`/api/transfers` 的请求体是严格模式（`ConfigDict(extra="forbid")`），字段有长度与控制字符校验；任务 id 是 `uuid4().hex`，不可预测。

## 6. 数据落盘位置

| 内容 | 位置 | 说明 |
|---|---|---|
| 非敏感配置 | `%APPDATA%\LANDrop\config.json` | 主机、端口、用户名、目录、认证方式、私钥路径、热键；**不含密码** |
| 主机指纹 | `%APPDATA%\LANDrop\known_hosts` | 应用私有，不动 `~/.ssh/known_hosts` |
| 密码 | Windows Credential Manager | 条目名 `LANDrop/<username>`，`CRED_TYPE_GENERIC`，机器级持久 |
| 远端临时文件 | `<远端目录>/<文件名>.landrop.part` | 失败/取消后保留，供下次续传 |
| 远端最终文件 | `<远端目录>/<文件名>` | 只有校验通过并改名后才出现 |

几个实现细节：

- `config.json` 写入用"临时文件 + `os.replace`"（`config.py:65`），避免写入过程中断电留下半个文件。
- 读到含 `password` 字段的配置会直接报错，而不是忽略它（`config.py:54`）——为了在旧版本或手改文件把明文密码写进来时明确告警。
- 凭据管理器通过 `ctypes` 直接调 `advapi32` 的 `CredWriteW/CredReadW/CredDeleteW`（`credentials.py`），不引入 `pywin32` 依赖，打包体积更小。非 Windows 平台明确抛错，不会退化成明文保存。

## 7. 进程与资源生命周期

| 事件 | 行为 |
|---|---|
| 应用启动 | Rust `setup()` 启动 sidecar 并等就绪，失败不阻塞窗口（UI 显示"服务不可用"）。开发模式启动 `python -m landrop.api.app`，安装后启动 `landrop-service\landrop-service.exe`。sidecar 是 GUI 子系统，不显示控制台窗口；异常写入 `%APPDATA%\LANDrop\service.log` |
| 窗口关闭请求 | `on_window_event` 里 `stop()`，kill 子进程并 `wait()`（`lib.rs:43`） |
| 应用退出 | `RunEvent::Exit` 再 `stop()` 一次（幂等）（`lib.rs:53`） |
| 应用崩溃/被强杀 | Job Object 句柄随进程销毁而关闭，OS 连同 Python 子进程一起杀掉（`job.rs`） |
| Python 服务退出 | FastAPI lifespan 里 `TransferManager.close()`：给所有任务置取消位，再 `shutdown(wait=True)` 等线程收尾 |
| 传输线程内异常 | 分类映射：`TransferCancelled` → cancelled；`TransferError/ValueError` → failed 且错误文本回传；其他异常 → 只回传异常类名，细节进本地日志（`app.py:278`） |

## 8. 前端实现要点

- **单一 store**（`transfer.ts`），没有 Vuex/Pinia。`reactive` 放表单，`ref` 放任务列表与状态；`computed` 派生 `isLocked`、`canSend`、`activeTask`。
- **锁定**：`isLocked` 在任务处于 `running`/`queued` 时为真，所有连接输入框 `:disabled`，避免传输途中改参数导致任务与表单不一致（`transfer.ts:63`）。
- **可选性**：`canSend` 同时要求文件已选、host/username/remoteDir 非空、没有运行中任务、服务 ready（`transfer.ts:68`）。
- **浏览器降级**：检测 `window.__TAURI_INTERNALS__`。没有它就把 `serviceState` 置为 error 并提示"浏览器预览模式"，同时文件选择填入假路径——只用于看布局，不假装能传（`transfer.ts:151`）。
- **热键**：启动时从配置读 `hotkey_modifiers`/`hotkey_key`，拼成加速键字符串（如 `Ctrl+Alt+space`）注册，回调 `invoke('show_main_window')`。注册失败（被别的程序占用）只把状态文字改成"快捷键被占用"，不影响任何其他功能。左下角头像可手动注销/重注册；「设置全局快捷键」打开编辑器改修饰键和主键，应用时先注销旧键、试注册新键，失败则回滚并恢复旧键，成功才写配置。浏览器预览模式下不注册，只提示"仅桌面版支持快捷键"。
- **能力最小化**：`capabilities/default.json` 只开了 `core:default`、`dialog:allow-open`、global-shortcut 的 register/unregister/is-registered。没有暴露 shell，也没有泛化文件系统访问。CSP 里 `connect-src` 只允许 `ipc:` 与 `ipc.localhost`。

Tauri 只暴露三个 command：`show_main_window`、`service_status`（启动并返回 endpoint/令牌）、`service_info`（只查询，不启动）。

## 9. 接口一览

所有接口都要求令牌。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 就绪探测，返回 `{"status":"ready"}` |
| GET | `/api/config` | 读非敏感配置 |
| PUT | `/api/config` | 写配置（含热键字段） |
| POST | `/api/hostkeys/probe` | 读远端主机密钥与指纹，返回 `trusted` |
| POST | `/api/hostkeys/trust` | 指纹复核通过后写入应用 known_hosts |
| GET | `/api/credentials/{username}` | 是否已存密码 |
| PUT | `/api/credentials` | 写入凭据管理器 |
| DELETE | `/api/credentials/{username}` | 删除 |
| POST | `/api/transfers` | 创建任务，202 返回首个快照 |
| GET | `/api/transfers/{id}` | 任务快照 |
| GET | `/api/transfers/{id}/events` | SSE 进度，支持 `Last-Event-ID` |
| POST | `/api/transfers/{id}/cancel` | 置取消位，保留 `.part` |
| POST | `/api/transfers/{id}/retry` | **新建**一个任务（新 id）续传同一文件 |

快照字段：`id / status / phase / sent / total / speed / message / error / result / request`。`result` 只在成功时出现，含 `remote_path`、`size`、`sha256`、`resumed_from`。`request` 里永远没有 `password`（有测试专门断言这一点）。

SSE 帧格式：

```
id: 7
data: {"id":"…","status":"running","phase":"transferring","sent":1048576,"total":52428800,"speed":9437184.0,"message":"正在传输", …}

```

重试的语义值得强调：`retry` 不复用旧任务对象，而是复制请求、生成新 id、重新提交。旧任务保持终态不变，历史可追溯；新任务从 `.part` 的实际长度继续。

## 10. 错误与边界条件处理

| 场景 | 行为 | 位置 |
|---|---|---|
| 远端首次出现、未确认指纹 | 连接被 `RejectPolicy` 拒绝，提示先检查并保存指纹 | `resume.py:160` |
| 指纹变化 | 拒绝连接；`trust()` 也拒绝保存 | `hostkeys.py:129` |
| 最终文件已存在 | 失败并提示，不静默覆盖 | `resume.py:182`、`resume.py:79` |
| 覆盖但服务端不支持原子改名 | 报错，旧文件与完整 `.part` 都保留 | `resume.py:82` |
| `.part` 比本地文件大 | 判定冲突，不截断、不当成功 | `resume.py:187` |
| `.part` 恰好等于本地大小 | 不重传，只做长度 + SHA-256 校验后发布 | `resume.py:188` |
| 传输中本地文件被改 | 提交前复核 `(size, mtime_ns)`，不一致则失败 | `resume.py:210`、`resume.py:223` |
| 哈希不一致 | 失败，保留 `.part`，不改名 | `resume.py:219` |
| 用户取消 | 置 `threading.Event`，循环内检查；关闭句柄，`.part` 保留 | `resume.py:203`、`app.py:234` |
| 重试一个还在跑的任务 | 400，提示只有已结束任务可重试 | `app.py:212` |
| 未知异常 | 只回传异常类名，详细堆栈进本地日志 | `app.py:282` |
| 令牌错误/缺失 | 401，带 `WWW-Authenticate: Bearer` | `app.py:356` |
| 非 loopback 或非法 Origin | 403 | `app.py:334` |
| sidecar 30 秒未就绪 | 杀掉子进程并报"未能在限定时间内就绪" | `service.rs:79` |

## 11. 安全设计清单

- 本机服务只绑 loopback，且中间件二次校验客户端地址。
- 每次启动生成新令牌，常数时间比较；令牌不落盘、不进 URL、不进日志。
- WebView 只拿到 `{baseUrl, token}`，拿不到任何 SSH 凭据；密码从表单直接进请求体，服务端用完即弃（任务对象 `finally` 里清空）。
- 密码持久化只经 Windows Credential Manager；配置文件里出现 `password` 字段直接报错。
- 主机密钥 trust-on-first-use，且"保存"前二次探测复核指纹；未知与变更一律拒绝。
- 远端文件名取本地 basename 拼接，用户填的目录不会被文件名逃逸。
- 覆盖只在服务端支持原子 `posix_rename` 时执行，绝不"先删后改"。
- Tauri capabilities 最小化；CSP 限制 `connect-src`。
- 未预期的异常不回传内部路径或堆栈。

## 12. 打包与发布

产物是**一个 NSIS 安装包**，装完的机器不需要 Node 或 Python。

### 12.1 两个阶段

```
npm run package   ≡   ① PyInstaller onedir  →  src-tauri/sidecar/landrop-service/
                      ② tauri build         →  LANDrop_0.1.0_x64-setup.exe
```

顺序不能反：`tauri.conf.json` 的 `bundle.resources` 把 `sidecar/landrop-service/` 映射成安装目录下的 `landrop-service/`，打包时这个目录必须已经存在。

也可以手动分两步跑：

```powershell
python -m PyInstaller --noconfirm --distpath src-tauri/sidecar --workpath build landrop-service.spec
npm run tauri build
```

### 12.2 sidecar 为什么是 onedir 而不是单文件

PyInstaller 的 `--onefile` 每次启动都要把自身解压到临时目录，44 MB 的载荷意味着数秒冷启动，而 Tauri 只给 30 秒就绪窗口。`onedir` 直接以目录形式随安装包分发，启动接近瞬开。代价是安装目录里有 730 个文件，用户不可见也不需要关心。

`landrop-service.spec` 里几个关键点：

- `name="landrop-service"` 与 `COLLECT(name=...)` 都必须是这个名字，Tauri 与 Rust 侧按固定路径查找。
- `hiddenimports` 显式列出 uvicorn 的协议实现（它按字符串动态导入 `uvicorn.protocols.http.h11_impl` 等），漏掉会在运行时才炸。
- `excludes` 排掉 `jedi`/`parso`/`IPython`/`numpy` 等。它们不是本项目的依赖，而是 PyInstaller 扫描 site-packages 时被牵连进来的——第一版没排，`jedi` 一个包就贡献了 22 MB。
- `console=False`：必须是 GUI 子系统。若设成 `console=True`，Windows 会为 sidecar 分配一个可见控制台窗口——主程序是 GUI 进程、没有控制台可继承，而 `Stdio::null()` 只重定向流、不阻止控制台创建，结果是每次启动都弹一个黑窗。诊断信息改写到 `%APPDATA%\LANDrop\service.log`。
- `disable_windowed_traceback=True`：窗口模式下一旦未捕获异常，PyInstaller 默认会弹模态错误框；关掉它，异常连同堆栈写入上面的日志文件。

体积演进：第一版 77 MB → 排除无关包后 44 MB → 安装包压缩后 19.25 MB。

### 12.3 安装后的目录结构

```
%LOCALAPPDATA%\LANDrop\
  landrop-desktop.exe          # Tauri 主程序
  landrop-service\
    landrop-service.exe        # PyInstaller 引导程序
    _internal\                 # Python 运行时、依赖、标准库
  uninstall.exe
```

`service.rs` 的 `packaged_service()` 按这个顺序找 sidecar：

1. `<exe目录>/landrop-service/landrop-service.exe` ← NSIS 实际布局
2. `<exe目录>/resources/landrop-service/landrop-service.exe` ← MSI 布局，预留未验证
3. `<exe目录>/landrop-service.exe` ← 便携版布局

都找不到时（release 构建）报错会带上已查找的完整路径，而不是笼统的"找不到程序"。

用户数据不在安装目录：配置与 `known_hosts` 在 `%APPDATA%\LANDrop`，凭据在 Windows 凭据管理器。所以卸载或覆盖升级都不会丢配置。

排查用日志：sidecar 是 GUI 子系统，没有控制台输出。服务启动失败、未捕获异常及其堆栈都写到 `%APPDATA%\LANDrop\service.log`。如果界面一直显示"本机服务不可用"，先看这个文件。

### 12.4 NSIS 工具链与国内网络

Tauri 首次打包会从 GitHub 下载 NSIS 3.13 与 `nsis_tauri_utils.dll`，解压到 `%LOCALAPPDATA%\tauri\NSIS`。若直连 GitHub 超时（表现为 `failed to bundle project: timeout: global`），可以手动填充缓存：

```powershell
# 1) 用任意可达的镜像下载两个文件
#    https://github.com/tauri-apps/binary-releases/releases/download/nsis-3.13/nsis-3.13.zip
#    https://github.com/tauri-apps/nsis-tauri-utils/releases/download/nsis_tauri_utils-v0.5.3/nsis_tauri_utils.dll

$cache = "$env:LOCALAPPDATA\tauri\NSIS"
# 2) 解开 nsis-3.13.zip，把其中的 Bin/ Include/ Plugins/ Stubs/ 等直接铺到 $cache
# 3) 插件必须放在这个精确位置（Tauri 的清单里写死了这四条）：
#      Bin/makensis.exe
#      Stubs/lzma-x86-unicode
#      Stubs/lzma_solid-x86-unicode
#      Plugins/x86-unicode/additional/nsis_tauri_utils.dll
```

插件目录是 `Plugins/x86-unicode/additional/`，不是 `Plugins/x86-unicode/`。放错位置 Tauri 会判定"目录缺失文件"并重新下载，等于白做。

校验用的是文件 SHA-1（`nsis_tauri_utils.dll` 应为 `75197FEE3C6A814FE035788D1C34EAD39349B860`），不是 Git blob 哈希。下载后可先核对再放入。

### 12.5 实测验收记录

在开发机上完整跑过一遍：

1. **sidecar 独立可用**：直接运行 `landrop-service.exe` 并注入端口/令牌环境变量，`/health` 返回 200，`/api/config` 返回默认配置，无令牌返回 401。
2. **真实传输可用**：让打包后的 sidecar 对着 `tests/sftp_server.py` 起的内存 SFTP 服务跑完整流程——probe 指纹、trust 保存、`POST /api/transfers`、轮询到 `succeeded`、远端文件字节与 SHA-256 一致。这一步验证的是 `cryptography` 等 C 扩展冻结后仍正常，也是 PyInstaller 最常出问题的地方。
3. **安装包可安装**：`/S` 静默安装，产物落在 `%LOCALAPPDATA%\LANDrop`，结构如上，sidecar 730 个文件齐全。
4. **安装后可运行**：启动 `landrop-desktop.exe` 后自动拉起 `landrop-service.exe` 子进程，在随机 loopback 端口监听；用 `taskkill /F` 强杀主进程后子进程同样消失（Windows Job Object 生效）。
5. **可卸载**：`uninstall.exe /S` 后安装目录完全移除。

## 14. 已知限制与未完成项

**发布相关**
- 只产出 NSIS 安装包（`bundle.targets` 设为 `["nsis"]`），没有 MSI。`service.rs` 已兼容 MSI 的 `resources/` 嵌套布局，但未实际验证。
- 安装包未做代码签名，首次运行会出现 SmartScreen 警告。
- 没有自动更新机制，升级需重新下载安装包覆盖安装（用户配置在 `%APPDATA%\LANDrop`，不会被覆盖）。
- 首次打包需要联网下载 NSIS 工具链，见下一节。
- CSP 的 `connect-src` 已加入 `http://127.0.0.1:*`，打包后前端才能调用随机端口的本机服务。开发模式下页面由 Vite 提供、CSP 不生效，所以这个问题只在打包后暴露；如果将来改了端口策略，这里要同步。
- 字体从 `fonts.googleapis.com` 在线加载（`style.css:1`），离线时会回落到 `Segoe UI`，不影响功能但会让界面与设计稿有差异。已知且暂不处理。

**功能缺口**
- 单文件、单任务：`TransferManager` 虽有 2 个工作线程，但 UI 一次只允许提交一个（`canSend` 里判 `isLocked`）。
- 前端固定 `overwrite: false`，界面没有覆盖确认入口；用户遇到"已存在"只能自己去远端改名或删文件。
- 热键默认 `Ctrl+Alt+Space`，从配置读取（`hotkey_modifiers` / `hotkey_key`）。左下角「设置全局快捷键」可改修饰键与主键，保存前会先试注册：被其他程序占用则回滚到原快捷键并提示，不会写坏配置。
- 无多设备配置；一次只保存一套 host/username/dir。
- 无速度限制、无自动重试上限策略、无传输后删除源文件。

**实现上的取舍，值得知道**
- 全文件 SHA-256 要额外读一遍远端。4 GiB 以上文件会明显拉长"校验中"阶段；这是用时间换"绝不发布坏文件"。
- 端口"先绑定再释放"存在极小的 TOCTOU 窗口，别的进程可能抢走。极端情况下表现为启动失败重试，不会降级成无鉴权。
- `ThreadPoolExecutor(max_workers=2)` 与任务表都只在内存：服务重启后历史任务丢失，但远端 `.part` 还在，用户重新发同一个文件仍可续传。
- 事件环形缓冲 256 条，超出后旧事件被丢弃；`Last-Event-ID` 过旧时只能靠快照接口对齐。

## 16. 下一步建议顺序

1. **真实主机验收**：Windows/Linux OpenSSH + >4 GiB 文件，跑一遍 [项目计划.md](项目计划.md) 阶段七的清单。打包已完成，但"装到另一台确实没装 Python 的机器上并把文件传出去"仍需要真人验一次。
2. **代码签名**：当前安装包未签名，首次运行会触发 SmartScreen。若要对外分发，需购买证书并在 `tauri.conf.json` 配 `bundle.windows.certificateThumbprint`。
3. **覆盖入口**：把 `overwrite` 接进 UI（冲突时弹确认），后端逻辑已就绪，只需一层交互。
4. 之后再考虑多文件队列与目录递归——这两项会实质改变任务模型（一个任务对应多个文件），改动面比打包大得多。
